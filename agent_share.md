### 3. Approval Evidence Fields (Mandatory Audit Schema)

Every phase gate transition recorded in `agent_share.md` or Kanban MUST include all 7 mandatory fields:
1. **`gate_name`**: Exact transition gate (e.g., `Propose-to-Apply`, `Close-Out-Authorization`, `Archive-Gate`).
2. **`human_approver`**: Explicit human supervisor identity (`Phuong`).
3. **`timestamp`**: Exact ISO-8601 timestamp with local offset (e.g., `2026-10-02T11:30:00+07:00`).
4. **`source_record`**: Traceable event or record ID (e.g., `meeting:2dfc376f-95fb-42d1-9835-59f4ace496eb`, chat event ID).
5. **`authorized_transition`**: Exact state pair (`[FROM_STATE] -> [TO_STATE]`).
6. **`approved_revision`**: Immutable commit SHA, artifact versions, and paths bound to the authorization.
7. **`evidence_pointers`**: Verifiable file paths to review findings (`reviews/findings-*.md`), audit reports, test logs, and validation output.

### 4. Asynchronous Handoff Rules (Direct-Chat Gap Bridge)

1. **Structured Assignment Contract**: Leader dispatches each task specifying:
   - `project_path`: Absolute path to project root (e.g., `O:\workspaces\oss\deskrpg`).
   - `change_id`: Active OpenSpec change slug (e.g., `room-creation-availability-and-validation-feedback`).
   - `task_id`: Kanban card ID tracking execution.
   - `sdlc_phase`: Current SDLC stage (`Explore`, `Propose`, `Apply`, `Verify`, `Archive`).
   - `output_contract`: Exact files, reports, or test evidence expected.
   - `approval_state`: Verified human authorization status.
2. **Artifacts Over Ephemeral Chat**: Communication between agents happens exclusively through structured on-disk artifacts (`proposal.md`, `specs/`, `design.md`, `tasks.md`, `reviews/findings-*.md`, reproducible test logs, diffs). Meeting minutes or verbal mentions never grant implementation permission.
3. **Read-Before-Write & Own-Section Discipline**: Always read `agent_share.md` completely before writing. Agents only edit their assigned rows, action items, and append chronological entries to the Updates Log (`[AGENT_ID] HH:MM: message`).
4. **File Ownership & Concurrency Locks**: Modify only files listed as 🔓 Unlocked in the File Ownership table. Mark 🔒 LOCKED while modifying; mark 🔓 Unlocked immediately upon completion.
5. **Fail-Closed Stop-and-Inform Gate**: If an approval is missing, records conflict, or approved scope changes, agents MUST HALT immediately, log `⚠️ CONFLICT: [description]` in the Updates Log, and await Human facilitation. Never guess or infer permission from Kanban column moves alone.
6. **Agent Recommendations vs. Human Authority**: Agent review verdicts (`APPROVED`, `PASS`) are technical evaluations only. **Only the Human Supervisor holds the authority** to approve phase transitions and archive changes.

### 5. Post-QA Close-Out Sequence (The 5-Step Lifecycle)

Once implementation passes Reviewer and QA audits, the team executes the mandatory 5-step close-out sequence:

```text
Step 5a: VERIFY               Step 5b: SYNC                 Step 5c: RE-VERIFY            Step 5d: ARCHIVE              Step 5e: AUDIT
┌──────────────────┐          ┌──────────────────┐          ┌──────────────────┐          ┌──────────────────┐          ┌──────────────────┐
│ openspec-verify- │   🛡️     │ openspec-sync-   │          │ Re-run 3D verify │   🛡️     │ openspec archive │          │ Post-Archive     │
│ change (3D: task │ ───────► │ specs (merge     │ ───────► │ on updated main  │ ───────► │ --skip-specs -y  │ ───────► │ Integrity Audit  │
│ + spec + design) │ [Human 1]│ delta to main)   │          │ specs & outputs  │ [Human 2]│ (relocate folder)│          │ (4-point matrix) │
└──────────────────┘          └──────────────────┘          └──────────────────┘          └──────────────────┘          └──────────────────┘
```

1. **Step 5a — 3D Verification (`openspec-verify-change`)**:
   - Load `.agents/skills/openspec/openspec-verify-change/SKILL.md` via `read_file()`.
   - Verify Completeness (tasks checked vs files touched), Correctness (spec scenarios vs test evidence), and Coherence (design decisions vs implementation).
   - Run CLI validation: `openspec validate "<change-name>" --strict`.
2. 🛡️ **Human Gate 1 — Synchronization Authorization**:
   - Present verification report to Human Supervisor.
   - Await explicit human approval before touching permanent specs in `openspec/specs/`.
3. **Step 5b — Intelligent Spec Synchronization (`openspec-sync-specs`)**:
   - Load `.agents/skills/openspec/openspec-sync-specs/SKILL.md` via `read_file()`.
   - Intelligently merge delta specs (`changes/<name>/specs/`) into permanent specs (`openspec/specs/`).
   - Carry added/modified requirements and scenarios verbatim; preserve existing untouched requirements.
4. **Step 5c — Post-Sync Re-Verification**:
   - Re-run `openspec-verify-change` to confirm main specs match all delta requirements and compiled outputs reflect changes.
5. 🛡️ **Human Gate 2 — Archive Authorization**:
   - Present sync evidence to Human Supervisor.
   - Explicitly ask: *"Approve archive?"* and wait for unambiguous human confirmation. NEVER use `--yes` without human sign-off.
6. **Step 5d — Change Archival (`openspec-archive-change`)**:
   - Load `.agents/skills/openspec/openspec-archive-change/SKILL.md` via `read_file()`.
   - Run: `openspec archive "<change-name>" --skip-specs -y` (spec updates already completed in 5b).
   - Relocates change to `openspec/changes/archive/YYYY-MM-DD-<name>/` and archives Kanban cards.
7. **Step 5e — Post-Archive Integrity Audit (MANDATORY)**:
   - QA executes post-archive integrity verification:
     1. *Requirement Count Check*: `### Requirement:` counts match between main spec and archived delta.
     2. *Line Count Check*: Main spec line count >= delta spec line count.
     3. *Compiled Output Cross-Check*: Verify runtime SKILL.md, templates, and config files against updated main specs.
     4. *Audit Artifact*: Save report to `openspec/workspace/audits/{YYYY-MM-DD}/<change-name>-audit.md`.
